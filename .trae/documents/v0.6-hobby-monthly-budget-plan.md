# v0.6 兴趣消费预算与超额警告 实施计划

## 1. 摘要

在现有 v0.5（每日额度 + 超支 FIFO 填补）之上，新增「按月」的兴趣消费预算：

- `settings` 新增 `hobby_monthly_budget`（整数分，`0` = 未设置），无表结构迁移。
- 只统计**带「爱好」标签的 `expense` 记录**，按自然月汇总；收入和其他标签一律不计。
- `GET /api/summary` 新增 `hobbyMonthlyBudget` / `hobbySpentThisMonth` / `hobbyRemaining`。
- `POST` / `PATCH /api/records` 成功保存后，若该记录是「爱好 + 支出」且导致所在月份总额超预算，仍返回原状态码，只在响应体追加 `warning: "本月兴趣消费已超额"`。
- 设置弹窗新增「每月兴趣消费预算（元）」；大盘新增「本月兴趣预算剩余」；保存触发超额时页面顶部出现红色可关闭提示。
- **不改动** `computeOverBudget`、不改动时间轴/日历标红逻辑。

## 3. 具体改动

### 3.1 日期工具：`server/dates.js`

新增自然月边界函数，供 summary 与 records 共用：

```js
// 返回 dateStr 所在自然月的首末日（含），如 '2026-11-05' -> { start: '2026-11-01', end: '2026-11-30' }
export function monthBounds(dateStr) {
  const [year, month] = dateStr.split('-').map(Number);
  const start = `${dateStr.slice(0, 7)}-01`;
  // Date.UTC(year, month, 0) = 下月第 0 天 = 本月最后一天
  const lastDay = new Date(Date.UTC(year, month, 0)).getUTCDate();
  const end = `${dateStr.slice(0, 7)}-${String(lastDay).padStart(2, '0')}`;
  return { start, end };
}
```

### 3.2 数据库：`server/db.js`

不建表、不迁移列，只在现有 `db.exec` 建索引块里补一行：

```sql

```

理由：本月汇总与 `dailyNetStmt` 都按 `date` 区间过滤，一条索引即可覆盖；`settings` 新键天然免迁移。

### 3.4 汇总查询：`server/overview.js`

在模块顶层新增预编译语句（只扩展，不动 `computeOverBudget`）：

```js
// 爱好支出：一个 JOIN + 一次聚合，避免 N+1
const hobbySpentStmt = db.prepare(`
  SELECT COALESCE(SUM(r.amount_cents), 0) AS total
  FROM records r
  JOIN record_tags rt ON rt.record_id = r.id
  JOIN tags t ON t.id = rt.tag_id
  WHERE t.name = '爱好'
    AND r.type = 'expense'
    AND r.date >= ? AND r.date <= ?
`);

export function getHobbySpent(startDate, endDate) {
  return hobbySpentStmt.get(startDate, endDate).total;
}
```

**为什么这样写最简洁**：
- 三表 JOIN 直接走 `record_tags(record_id, tag_id)` 主键 + `tags.name` 唯一索引，聚合只返回一行标量，无需在 JS 里去重或分组（同一条记录即使重复关联也只 JOIN 一次，主键保证不重复）。
- 用 `t.name = '爱好'` 而不是 `tags.is_preset = 1`，与需求原文一致，也避免用户自建同名标签时漏算。
- 日期用 `>= start AND <= end` 的字符串区间（`YYYY-MM-DD` 定长），配合新增的 `idx_records_date` 可直接走索引区间扫描。

### 3.5 接口：`server/routes/summary.js`

```js

```

响应追加：

```js

```

### 3.6 记录写入：`server/routes/records.js`

新增一个纯函数（模块内，供 POST/PATCH 复用）：

```js
// 仅在「本条是爱好支出」且该月已超预算时返回警告文案
function hobbyWarningFor(record, hobbyBudget) {
  if (hobbyBudget <= 0) return null;
  if (record.type !== 'expense' || !record.tags.includes('爱好')) return null;

  const { start, end } = monthBounds(record.date);
  const spent = getHobbySpent(start, end);
  return spent > hobbyBudget ? '本月兴趣消费已超额' : null;
}
```

- **POST**：`createRecordTx` 之后，用 `toRecord(getStmt.get(id), tagNames(id))` 得到完整记录 → 调 `hobbyWarningFor` → `res.status(201).json({ ...record, warning })`（无警告时 `warning` 为 `null`，不改变原有字段结构，前端向后兼容）。
- **PATCH**：`saveRecordTx` 之后同样构造记录、判断，`res.json({ ...record, warning })`。
- **DELETE**：不返回警告。
- 需要 `import { getSettings } from '../settings.js'`，以及从 `overview.js` 引入 `getHobbySpent`、从 `dates.js` 引入 `monthBounds`。
- 判断放在事务提交后：读到的一定是最终落库状态，金额/标签/类型任意一项改动都能被覆盖，无需分支。

## 4. 关键问题回答

### 4.1 如何高效计算「本月爱好支出」

单条 SQL 完成，不把记录拉回 JS 再过滤：

```sql
SELECT COALESCE(SUM(r.amount_cents), 0) AS total
FROM records r
JOIN record_tags rt ON rt.record_id = r.id
JOIN tags t ON t.id = rt.tag_id
WHERE t.name = '爱好' AND r.type = 'expense'
  AND r.date >= ? AND r.date <= ?
```

- `tags.name` 有 `UNIQUE` 约束、`record_tags` 是复合主键，JOIN 天然去重，`SUM` 不会因多标签重复计算。
- 结果是一行 `total`，`better-sqlite3` 同步执行，O(当月爱好记录数)。
- 加 `idx_records_date` 后按日期区间先裁剪，再回 `record_tags` 取标签，数据量增大也不会退化成全表扫描。
- 全项目只有这一个 query 负责该口径，summary 与 records 警告共用，避免两处逻辑漂移。

### 4.2 跨月怎么处理

- 每次请求都用 `monthBounds(today)` 现算 `[本月 1 日, 本月最后一日]`，**没有任何累计状态**，所以 11-01 零点后第一次请求就自动变成 11 月区间，额度天然「刷新」，不需要定时任务或月末归档。
- `monthBounds` 用 `Date.UTC(year, month, 0)` 取月末，2 月（闰年 29 天）、30/31 天月份全部自动正确，不需要硬编码。
- 上个月的已花金额不会结转、不会影响下个月剩余；这与 v0.5 的「每日额度」是两套独立口径，互不干扰。

### 4.3 前端何时触发并显示警告

- **只在保存成功那一刻**：POST/PATCH 返回 201/200 且响应带 `warning` 时显示；不拦截保存（记录已经入库）。
- **不在页面加载时弹**：刷新页面、切日期、打开日历时都不弹，避免每次进入都骚扰；余额状态由大盘的「本月兴趣预算剩余」长期可见（负数红色）。
- **无警告即清除**：后续保存一条不超额的记录，会 `setHobbyWarning('')` 自动收起旧提示；用户也可点「知道了」手动关闭。
- **大盘同步**：保存后已有的 `loadSummary()` 会刷新，超额的负数立即出现在大盘栏。

## 5. 假设与决策

1. **「本月」的判定基准**：以**被保存记录自身的 `date` 所在月份**为准，而不是服务器当天。这样补记 10 月的爱好支出时，检查的是 10 月总额，语义更准确；记当月记录时两者等价。大盘的「本月」则取服务器当天所在自然月。
2. **预算为 0 视为未设置**：不产生任何警告（否则每笔爱好支出都会报警），大盘显示「未设置」。
3. **警告文本固定**：`本月兴趣消费已超额`，与需求原文一致；不附带具体差额，避免前端二次拼接。
4. **返回结构向后兼容**：`warning` 追加在记录对象上（无警告为 `null`），不改 `{ records }` / 单条记录既有字段，前端 `data.warning` 即可读取。
5. **不改 v0.5 逻辑**：`computeOverBudget`、`overBudgetDates`、时间轴/日历标红、`accounting_start_date` 全部保持原样。
6. **不使用 `records.is_hobby`**：该列历史遗留且始终为 0，兴趣判定只认标签名「爱好」，与需求一致。
7. **PUT 整包覆盖**：与现有 `dailyMaxBudget` 行为一致，前端始终提交全部三个设置字段。

## 6. 验证步骤

前置：`npm run dev` 已在运行（后端 3001 / 前端 5173）。

1. **默认值**
   - `GET /api/settings` → 含 `hobbyMonthlyBudget: 0`；`GET /api/summary` → `hobbyMonthlyBudget: 0`、`hobbySpentThisMonth: 0`、`hobbyRemaining: 0`。
2. **设置预算**
   - `PUT /api/settings` 传 `{"dailyMaxBudget":10000,"accountingStartDate":"2026-11-07","hobbyMonthlyBudget":10000}` → 返回 `hobbyMonthlyBudget: 10000`。
   - `PUT` 传 `hobbyMonthlyBudget: -1` → 400 `每月兴趣消费预算必须是不小于 0 的整数（单位：分）`。
3. **只算爱好 + 只算支出**
   - `POST /api/records` 一条 `{amount:"60", type:"expense", tags:["爱好"]}` → `GET /api/summary` 的 `hobbySpentThisMonth` 增加 6000，`hobbyRemaining` 减少 6000。
   - 再 POST 一条 `{amount:"500", type:"income", tags:["爱好"]}` → `hobbySpentThisMonth` **不变**（收入不计）。
   - 再 POST 一条 `{amount:"500", type:"expense", tags:["餐饮"]}` → `hobbySpentThisMonth` **不变**（标签不计）。
4. **超额警告**
   - 预算设 ¥100，已有爱好支出 ¥60；再 POST `{amount:"50", type:"expense", tags:["爱好"]}` → 状态码仍 201，响应含 `warning: "本月兴趣消费已超额"`，`hobbyRemaining` 为 `-1000`。
   - `PATCH /api/records/{该记录}` 改金额为 `100` → 200 且同样带 `warning`。
   - 再 POST 一条不带「爱好」的支出 → 响应 `warning` 为 `null`（不误报）。
5. **跨月隔离**
   - POST 一条 `{amount:"1000", type:"expense", tags:["爱好"], date:"2026-10-31"}`（预算 ¥100）→ 响应带 `warning`（10 月超支），但 `GET /api/summary` 的 `hobbySpentThisMonth` **不变**（11 月不受 10 月影响）。
6. **前端**
   - 设置弹窗出现「每月兴趣消费预算（元）」，预填当前值，保存后大盘立即更新。
   - 大盘显示「本月兴趣预算剩余」；预算 0 时显示「未设置 / 去设置」；超额时数字为红色负数。
   - 勾选「爱好」保存一条超额支出 → 页面顶部出现红色「本月兴趣消费已超额」，可点「知道了」关闭，表单不被阻塞；随后保存一条不超额的记录，提示自动消失。
7. **构建**
   - `npm run build -w client` 通过。
8. **清理**：删除步骤 3~5 产生的临时记录，确认 `hobbySpentThisMonth` 回到原值。
