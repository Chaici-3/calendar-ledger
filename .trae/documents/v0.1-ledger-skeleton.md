# v0.1 本地记账本骨架 — 实施计划

## Summary

目标：在空目录 `c:\Users\30837\Desktop\calendar-ledger` 搭出一个可运行的最小全栈记账本。

技术栈与形态（已确认）：

- 前端：React + Vite，目录 `client/`
- 后端：Node + Express，目录 `server/`
- 数据库：SQLite，驱动 `better-sqlite3`，文件落在 `server/data/ledger.db`
- 根目录用 npm workspaces + `concurrently`，一条 `npm run dev` 同时起前后端

v0.1 功能边界（严格不超出）：

1. 建三张表：`records`、`tags`、`settings`
2. 后端提供「存一条记录」「读全部记录」两个接口
3. 前端一个极简页面：金额输入框 + 保存按钮，保存后刷新页面仍能看到这条记录

**不做**：编辑/删除、收入支出分类、标签关联、设置项读写、登录、测试框架、完整 UI 设计。

## Proposed Changes

### 文件清单与创建顺序

按序号执行，前一步验证通过再进入下一步。

#### 第 1 步：工程根部

**1. `package.json`（根）**

- `"private": true`，`"workspaces": ["server", "client"]`
- devDependencies：`concurrently`
- scripts：
  - `dev`：`concurrently -n server,client -c blue,green "npm:dev:server" "npm:dev:client"`
  - `dev:server`：`npm run dev -w server`
  - `dev:client`：`npm run dev -w client`
- 理由：一次 `npm install` 装齐两端，一条命令起两个进程。

**2. `.gitignore`**

- 忽略 `node_modules/`、`server/data/*.db`、`server/data/*.db-journal`、`.env`

#### 第 2 步：后端

**3. `server/package.json`**

- `"type": "module"`
- dependencies：`express`、`better-sqlite3`
- scripts：`dev` = `node --watch index.js`，`start` = `node index.js`
- **不加** `cors`：前端走 Vite 代理，同源请求，无跨域问题

**4. `server/db.js`**

- 用 `better-sqlite3` 打开 `server/data/ledger.db`（先 `mkdir` 保证 `data/` 存在，用 `node:fs` 的 `mkdirSync(..., { recursive: true })`）
- 导出单例 `db`，并执行建表 SQL（`CREATE TABLE IF NOT EXISTS`，幂等）
- 三张表结构：

```sql
CREATE TABLE IF NOT EXISTS records (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  amount_cents INTEGER NOT NULL,           -- 金额，单位「分」，整数存储
  note         TEXT,                       -- 备注，v0.1 可为空，前端暂不填
  is_hobby     INTEGER NOT NULL DEFAULT 0, -- 是否爱好类支出，v0.1 前端不填，恒为 0
  created_at   TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

CREATE TABLE IF NOT EXISTS tags (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  name      TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

CREATE TABLE IF NOT EXISTS settings (
  key   TEXT PRIMARY KEY,
  value TEXT
);
```

- 决策：金额用整数「分」(`amount_cents`) 存，避免浮点误差；`tags`/`settings` 只建表，v0.1 不读写
- 决策：**不建** `record_tags` 关联表，因为需求明确只三张表；标签关联留到 v0.2

**5. `server/routes/records.js`**

- `express.Router()`
- `GET /`：`SELECT id, amount_cents, note, is_hobby, created_at FROM records ORDER BY id DESC` → `{ records: [...] }`
- `POST /`：
  - 入参 `{ amount }`（单位「元」，数字或字符串），可选 `note`、`isHobby`（0/1，缺省 0）
  - 校验：`amount` 转字符串后匹配 `/^\d+(\.\d{1,2})?$/`，且大于 0；不通过返回 400 `{ error: "..." }`
  - `isHobby` 校验：仅接受 `0`/`1`/`true`/`false`/缺省，其余 400；落库统一转成 `0`/`1`
  - 转换：按字符串拆分整数位与小数位算出 `amount_cents`（不用 `Number * 100`，避免二进制浮点尾差）
  - `INSERT INTO records (amount_cents, note, is_hobby) VALUES (?, ?, ?)`，用 `db.prepare(...).get(...)`/`lastInsertRowid` 取回新行 → 201 + 单条记录对象
- 返回值统一 camelCase：`{ id, amountCents, note, isHobby, createdAt }`，由后端做一次映射（DB 的 `is_hobby` 0/1 → `isHobby` 布尔），前端不关心下划线命名；v0.1 前端不写 `isHobby`，返回恒为 `false`

**6. `server/index.js`**

- `express()` + `express.json()`
- 挂载 `app.use('/api/records', recordsRouter)`
- `GET /api/health` → `{ ok: true }`（仅用于手工确认后端已启动，成本一行）
- 统一错误兜底：`app.use((err, req, res, next) => res.status(500).json({ error: 'internal error' }))`
- `listen(3001)`，启动时打印实际端口
- 不托管静态文件（前端由 Vite 负责），保持职责单一

#### 第 3 步：前端

**7. `client/package.json`**

- `"type": "module"`
- dependencies：`react`、`react-dom`
- devDependencies：`vite`、`@vitejs/plugin-react`
- scripts：`dev` = `vite`，`build` = `vite build`，`preview` = `vite preview`

**8. `client/vite.config.js`**

- `@vitejs/plugin-react`
- `server: { port: 5173, proxy: { '/api': 'http://localhost:3001' } }`
- 理由：前端所有请求走相对路径 `/api/...`，开发时由 Vite 转发到 Express，因此后端无需 CORS

**9. `client/index.html`**

- 标准 Vite 入口，`<script type="module" src="/src/main.jsx">`，`lang="zh-CN"`

**10. `client/src/main.jsx`**

- `createRoot` 挂载 `<App />`，引入 `App.css`

**11. `client/src/App.jsx`**

- state：`amount`（输入框字符串）、`records`（列表）、`saving`、`error`
- 挂载时 `GET /api/records` 填充列表（刷新页面能看到历史记录，即验收点）
- 表单 submit：`POST /api/records`，body `{ amount }`；成功后清空输入框并重新拉取列表
- 失败时在页面上显示后端返回的 `error` 文案，不静默失败
- 列表渲染：`第 id 条 · ¥(amountCents / 100).toFixed(2) · createdAt`
- 不额外抽 `api.js`：仅两处 fetch，直接在组件内写完，避免为一次性操作建抽象

**12. `client/src/App.css`**

- 极简样式：居中容器、输入框、按钮、列表行分隔。不做设计系统

## Assumptions & Decisions

| 项 | 决定 | 理由 |
|---|---|---|
| 金额存储 | 整数 `amount_cents`（分） | 记账必须避免浮点误差 |
| 输入单位 | 前端输入「元」，后端转「分」 | 用户直觉；接口返回 `amountCents` 供前端展示 |
| `tags` / `settings` | 仅建表，v0.1 不读写 | 满足「建三张表」要求，不提前做功能 |
| `is_hobby` | 建表即有，`NOT NULL DEFAULT 0`；v0.1 前端不填、不展示，POST 可不传 | 按要求先落字段；API 输出 `isHobby` 布尔值 |
| 记录与标签关系 | 暂不建第四张关联表 | 用户明确只要三张表 |
| CORS | 不加 `cors` 依赖，用 Vite proxy | 减少依赖，同源请求 |
| 端口 | 后端 3001，前端 5173 | 避开 3000 常见占用 |
| 热重载 | 后端 `node --watch`（Node 22 内置） | 不引入 nodemon |
| 数据库文件 | `server/data/ledger.db`，不入库 | 本地数据不提交 |
| 测试 | 不写自动化测试，手工验证 | v0.1 骨架，避免过度工程 |
| 文档 | 只产出本计划文件，不写 README | 未被要求 |

## Verification

1. **安装**：在项目根目录 `npm install`（workspaces 一次性装齐；`better-sqlite3` 若有预编译包会直接下载，无则本地编译）
2. **启动**：`npm run dev`，确认两个进程都起来，日志显示后端 3001、前端 5173
3. **后端接口（新开一个终端）**
   - `Invoke-RestMethod http://localhost:3001/api/health` → `ok: true`
   - `Invoke-RestMethod -Method Post -Uri http://localhost:3001/api/records -ContentType 'application/json' -Body '{"amount":"12.50"}'` → 返回新记录，`amountCents` 为 `1250`，`isHobby` 为 `false`
   - `Invoke-RestMethod http://localhost:3001/api/records` → `records` 中含刚才那条，且带 `isHobby`
   - 负例：body `{"amount":"-5"}` 与 `{"amount":"abc"}` 都应返回 400
   - 显式传 `{"amount":"8","isHobby":1}` → 返回 `isHobby: true`
4. **数据库落盘校验**
   - `node -e "const D=require('better-sqlite3');const d=new D('server/data/ledger.db',{readonly:true});console.log(d.prepare(\"select name from sqlite_master where type='table'\").all())"`（在根目录执行）→ 应列出 `records`、`tags`、`settings`
   - 再查一条记录，确认 `is_hobby` 字段存在且值为 `0`
5. **前端验收**：浏览器打开 `http://localhost:5173` → 输入 `12.5` → 点保存 → 列表出现该条 → **按 F5 刷新后仍在**（核心验收点）
6. **异常路径**：输入 `0` 或 `abc` 点保存，页面显示错误提示且列表不变
