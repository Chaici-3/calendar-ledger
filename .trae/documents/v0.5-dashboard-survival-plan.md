# v0.5 记账本 — 收支类型、总览大盘与生存目标 实施计划

## Summary

在 v0.4 上新增三个能力，不动时间轴、标签和现有 CRUD 契约：

1. **收支类型**：`records.type`（`expense` / `income`），POST/PATCH 支持 `type`
2. **全局配置**：启用 `settings` 表（`initial_balance` / `survival_start_date` / `survival_end_date` / `daily_min_budget`），新增 `GET/PUT /api/settings`
3. **总览大盘**：`GET /api/summary` 服务端聚合初始资金、总收入/总支出、当前余额、今日收/支/结余、生存目标状态与每日额度；前端在右侧最上方新增大盘栏
4. **前端交互**：新增表单加「支出/收入」切换；新增设置弹窗（初始资金、生存起止、每日最低底线）；列表收入记录用 `+¥` 绿色区分

**不做**：兴趣预算、Agent、生存目标的额外提醒/动画；不修改时间轴、标签、日期筛选逻辑。

改动 10 个文件（5 个新建）：`server/db.js`、`server/dates.js`（新）、`server/settings.js`（新）、`server/routes/settings.js`（新）、`server/routes/summary.js`（新）、`server/routes/records.js`、`server/index.js`、`client/src/App.jsx`、`client/src/components/SummaryBar.jsx`（新）、`client/src/components/SettingsModal.jsx`（新）、`client/src/App.css`（样式追加，算第 11 个文件）。零新增依赖。

## Proposed Changes

### 1. `server/db.js` — records 补 type

- 迁移（幂等）：

```js
const hasTypeColumn = db
  .prepare("SELECT name FROM pragma_table_info('records')")
  .all()
  .some((column) => column.name === 'type');

if (!hasTypeColumn) {
  db.exec(
    "ALTER TABLE records ADD COLUMN type TEXT NOT NULL DEFAULT 'expense' CHECK (type IN ('expense','income'))"
  );
}
```

- 旧记录由 `DEFAULT` 补成 `expense`；`CHECK` 在数据库层兜底，API 校验仍是第一道
- `settings` 表结构不动（`key/value` 都是 TEXT），不新增列、**不预插默认行**（原因见第 3 点）

### 2. `server/dates.js`（新）— 服务端日期工具

从 `records.js` 抽出、行为不变：

- `todayLocal()` → `YYYY-MM-DD`
- `parseDate(raw)` → 严格校验（含 `2026-02-30` 拒绝），无效返回 `null`
- 新增 `diffDaysInclusive(from, to)`：`Date.UTC(to) - Date.UTC(from)` / 86400000 **+ 1**，两端都算整天；用 UTC 纯日期避免本地夏令时干扰
- `records.js` 改为 `import { todayLocal, parseDate } from '../dates.js'`，删除本地副本（唯一对既有代码的改动，逻辑等价）

### 3. `server/settings.js`（新）— 默认值、读取、校验（重点一）

**默认值初始化策略：不写数据库，读取时合并。** `settings` 里只有用户显式保存过的 key；`getSettings()` 返回：

```js
{
  initialBalance: 0,        // 分
  survivalStartDate: null,
  survivalEndDate: null,
  dailyMinBudget: 0,        // 分
}
```

- 读取：`SELECT key, value FROM settings` 后 `Object.fromEntries`，逐个按类型解析：
  - 整数字段（`initial_balance` / `daily_min_budget`）：`Number.parseInt(value, 10)`，非有限数或 < 0 → 回退默认 `0`（兼容脏数据）
  - 日期字段：`parseDate(value)`，无效/空 → `null`
- **为什么不在启动时插入默认行**：默认值属于业务口径，写进库后改默认值就要再迁移；读取时合并可让旧库、空库、半配置库都得到同一份完整结构，也不会把「用户没设置」和「用户设置成 0」混在一起（后者只影响显示提示，前者更明确）
- 写入（`saveSettings(input)`）：
  - `initialBalance` / `dailyMinBudget`：必须是 **整数分且 ≥ 0**，否则 400
  - `survivalStartDate` / `survivalEndDate`：要么两者都为 `null`（或空串），要么两者都是合法日期且 `start <= end`；只给一个 → 400
  - PUT 语义是**整体覆盖**：未传或为 `null` 的字段回到默认值；未知 key 忽略
  - 落地：`INSERT INTO settings (key, value) VALUES (?, ?) ON CONFLICT(key) DO UPDATE SET value = excluded.value`；日期置空时直接 `DELETE FROM settings WHERE key = ?`，避免残留空串
  - 全部写入包在 `db.transaction()` 中，避免半套配置

### 4. `server/routes/settings.js`（新）— `GET/PUT /api/settings`

- `GET /` → `{ settings: getSettings() }`，永不为空、永不因缺字段报错
- `PUT /` → 校验 → 保存 → 返回 `{ settings: getSettings() }`
- 错误信息与现有风格一致（中文短句，400）

### 5. `server/routes/summary.js`（新）— `GET /api/summary`

**服务端固定 3 条查询**（与记录数无关）：

1. `SELECT type, SUM(amount_cents) AS total FROM records GROUP BY type` → 总收入/总支出
2. `SELECT type, SUM(amount_cents) AS total FROM records WHERE date = ? GROUP BY type`（`? = todayLocal()`）→ 今日收/支
3. `getSettings()`（内部一条 `SELECT`）

**返回结构**

```json
{
  "initialBalance": 100000,
  "totalIncome": 50000,
  "totalExpense": 20000,
  "currentBalance": 130000,
  "todayIncome": 0,
  "todayExpense": 1200,
  "todayBalance": -1200,
  "survival": {
    "startDate": "2026-11-01",
    "endDate": "2026-11-10",
    "status": "active",
    "remainingDays": 6,
    "dailyLimit": 21666
  }
}
```

- `currentBalance = initialBalance + totalIncome - totalExpense`（可为负）
- `todayBalance = todayIncome - todayExpense`
- `dailyLimit = Math.floor(currentBalance / remainingDays)`，整数分；仅 `status ∈ {upcoming, active}` 且 `remainingDays > 0` 时计算，否则 `null`（**除以 0 的异常在这里被挡住**，前端只判 `null`）
- `dailyMinBudget` 只随 `GET /api/settings` 返回，**不参与 `dailyLimit` 公式**（需求只定义为「余额 ÷ 剩余天数」，不擅自加规则）

**生存剩余天数（重点二）**

统一用「今天」`today = todayLocal()`，`remainingDays` **含起止两端整天**：

| 场景 | 判定 | `status` | `remainingDays` | `dailyLimit` |
|---|---|---|---|---|
| 未设置（任一日期缺失） | — | `none` | `null` | `null` |
| 目标还没开始 | `today < start` | `upcoming` | `diffDaysInclusive(start, end)`（整段周期） | `floor(balance / remainingDays)` |
| 已在周期内 | `start <= today <= end` | `active` | `diffDaysInclusive(today, end)`（含今天） | 同上 |
| 已结束 | `today > end` | `ended` | `0` | `null` |

举例（今天 `2026-11-05`）：

- `11-01 ~ 11-10` → `active`，剩余 `6` 天（5、6、7、8、9、10）
- `11-20 ~ 11-30` → `upcoming`，剩余 `11` 天（20…30）
- `10-01 ~ 11-01` → `ended`，剩余 `0`，额度 `null`
- 周期最后一天 `end = today` → `active`，剩余 `1` 天，额度 = 全部余额

日期合法性由 PUT 保证（`start <= end`）；`summary` 仍做防御：读取时若 `start > end`，按 `none` 处理，不抛错。

**大盘刷新策略（重点三）**

- **不做轮询/WebSocket**，也不在前端自己算余额与生存天数：服务端聚合是唯一口径，前端只缓存一份 `summary`

  2. `POST /api/records` 成功后

  4. `DELETE /api/records/:id` 成功后
  5. 设置保存成功后

```js
async function loadSummary() {
  const res = await fetch('/api/summary');
  const data = await res.json();
  if (!res.ok) throw new Error(data.error ?? '大盘加载失败');
  setSummary(data);
}
```

**列表**

- 合计仍按金额绝对值求和，不改 v0.2/v0.3 的合计逻辑；`今日合计` 文案与数值不变（现有合计不区分收支，本次不擅自改）

## Assumptions & Decisions

| 项 | 决定 | 理由 |
|---|---|---|
| settings 默认值 | 不入库，读取时合并默认 `{0, null, null, 0}` | 空库/半配置都能返回完整结构；改默认值无需迁移 |
| 脏数据容错 | 整数解析失败或 <0 → 0；日期非法 → null | 大盘永远可渲染 |
| PUT 语义 | 整体覆盖，缺省/`null` 回默认，空日期删 key | 与前端整表单提交一致，避免残留 |
| 生存剩余天数 | 含今天、含结束日；未来目标按整段周期；已结束为 0 | 口径明确，且保证最后一天额度=全部余额 |
| 除零 | `remainingDays = 0` 时 `dailyLimit = null` | 不产生 `Infinity/NaN` |
| 每日额度公式 | `floor(balance / days)`，不用 `dailyMinBudget` 参与 | 需求原文公式；min budget 仅存储备用 |
| 今日结余 | 服务端按 `today` 聚合，与所选日期无关 | 用户切到历史日期时「今日」仍应指真实今天 |
| 大盘刷新 | 仅挂载 + 5 类写操作成功后重拉，无轮询 | 单接口聚合，避免前端重复计算；数据量小，够实时 |
| 合计 | 保持「金额绝对值求和」，不改成净收支 | 明确不修改现有合计逻辑 |
| type 显示 | 收入 `+¥` 绿色，支出沿用 `¥` | 最小可视化区分 |
| 行内编辑 type | 不做 | 本版只要求新增切换；后端已支持 |
| 迁移 | `ALTER TABLE ... DEFAULT 'expense' CHECK(...)` | 旧数据自动保底，库层兜底 |
| 依赖 | 无新增 | 计算全在现有 Node/React 内完成 |

## Verification

1. **迁移**
   - `PRAGMA table_info(records)` → `type` 存在、`notnull=1`、默认 `'expense'`
   - 旧记录 `type` 全部为 `expense`
   - 直接 SQL 插入 `type='abc'` 被 CHECK 拒绝
2. **记录接口**
   - `POST {"amount":"10","type":"income"}` → 201，`type:"income"`；不传 type → `expense`；`type:"abc"` → 400
   - `PATCH {"type":"income"}` → 返回 `type` 改变，金额/标签不受影响；`PATCH {"type":"abc"}` → 400；`PATCH {}` 仍 400
   - `GET /api/records?date=…` 每条含 `type`
3. **settings**
   - 空库 `GET /api/settings` → `{0, null, null, 0}`
   - `PUT` 全量 → 再 `GET` 一致；`initialBalance: 100000` 原样返回
   - 负整数 / 小数分 / 非数字 → 400
   - 只传开始日期 → 400；`start > end` → 400；两者 `null` → 清空
   - 重复 PUT 覆盖而非累加；空日期后 `settings` 表无残留行
4. **summary**
   - 无 settings：`initialBalance=0`，余额 = 收 - 支，`survival.status='none'`、`remainingDays=null`、`dailyLimit=null`
   - `11-01~11-10`（今天 11-05）→ `active`、`remainingDays=6`、`dailyLimit=floor(balance/6)`
   - `11-20~11-30` → `upcoming`、`remainingDays=11`
   - `end` 早于今天 → `ended`、`remainingDays=0`、`dailyLimit=null`（无 Infinity/NaN）
   - `end = today` → 剩余 1，额度 = 全部余额
   - 负余额 → `currentBalance` 为负，额度为负（floor），不报错
   - 今日收/支/结余与当天记录一致，切到历史日期后 `todayBalance` 仍指今天
5. **前端**
   - 大盘栏位于右侧最上方、日历栏之上；三块数据与接口一致，负数为红色
   - 未设置生存目标 → 不显示额度，显示「去设置」；点击打开设置弹窗
   - 设置弹窗预填现有值；保存后大盘立即更新；非法日期/金额有红字；`Esc`/遮罩可关
   - 新增表单切换「收入」后保存 → 列表显示 `+¥` 绿色；大盘总余额/总收入/今日结余同步变化
   - 编辑金额、删除记录后大盘同步刷新（无需手动刷新页面）
   - 切换日期/时间轴/标签筛选 → 大盘数值不变（全局口径）
   - 时间轴、日历弹窗、步长翻页、标签选择与行内编辑行为不变
6. **质量**
   - 浏览器控制台无报错；`npm run build` 通过；`client/package.json` 无新增依赖
