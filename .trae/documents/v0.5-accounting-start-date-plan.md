# v0.5 记账基准日（accounting_start_date）实施计划

## 1. 摘要

把「超支队列的绝对起点」从隐式的 `MIN(date)` 改为显式配置 `accounting_start_date`：

- `settings` 新增可选键 `accounting_start_date`（`YYYY-MM-DD`），不做表结构迁移（`settings` 本来就是 key/value）。
- 未设置时首次读取自动固定为当天（`todayLocal()`），只写一次，不再逐日漂移；删除最早记录也不会改变起点。
- `computeOverBudget` 的有效起点取 `max(accounting_start_date, MIN(date))`；起点之前的记录只计入总余额，不参与超支与结转。
- 设置弹窗新增 `type="date"` 的「记账基准日」输入；保存后 `App` 已有的 `onSaved → loadSummary()` 会立刻重算大盘与标红。

## 3. 具体改动

### 3.1 数据存储与迁移：`server/settings.js`

**迁移方式：不做 ALTER TABLE。** `settings` 是通用 key/value 表，直接新增一行 `accounting_start_date` 即可；旧库没有该行时按「未设置」处理。

1. 新增常量：
   ```js
   const ACCOUNTING_START_KEY = 'accounting_start_date';
   ```
2. `getSettings()` 增加 `accountingStartDate`：
   - 从 `stored[ACCOUNTING_START_KEY]` 取值，用 `parseDate()`（从 `dates.js` 引入）校验；
   - 若缺失或非法 → 取 `todayLocal()` 并**立即 upsert 写库**（只发生一次），达到「首次开启功能的日期被固定下来」的效果；
   - 返回 `{ dailyMaxBudget, accountingStartDate }`，保证调用方永远拿到一个合法日期。
3. `validateSettings(input)` 增加字段：
   - `accountingStartDate === undefined` → 返回 `undefined`（表示「未提供，保留原值」，避免只改额度时误清基准日）；
   - `null` 或 `''` → 返回 `null`（表示清空；读取时会重新固定为当天）；
   - 其他值必须能被 `parseDate()` 接受，否则返回 `error: '记账基准日格式应为 YYYY-MM-DD'`；
   - 允许未来日期（由算法层处理为「尚未开始」）。
4. `writeTx` 调整：
   - 原逻辑不变：upsert `daily_max_budget`，删除 `LEGACY_KEYS`；
   - `accountingStartDate === undefined` 时跳过；
   - `null` 时执行 `deleteStmt.run(ACCOUNTING_START_KEY)`；
   - 字符串时 upsert。
5. `saveSettings()` 仍返回 `getSettings()`，因此「清空后」会立刻返回重新固定的当天日期，前端可拿到确定值。

### 3.2 算法：`server/overview.js`

1. SQL 语句调整：
   - 新增 `const earliestStmt = db.prepare('SELECT MIN(date) AS earliest FROM records');`
   - 把 `dailyNetStmt` 改为按区间查询（保留 `ORDER BY date ASC`）：
     ```sql
     SELECT date,
            SUM(CASE WHEN type = 'income' THEN -amount_cents ELSE amount_cents END) AS net_expense
     FROM records
     WHERE date >= ? AND date <= ?
     GROUP BY date
     ORDER BY date ASC
     ```
2. 函数签名改为显式对象，便于扩展且避免参数顺序歧义：
   ```js
   export function computeOverBudget({ dailyMaxBudget, accountingStartDate }, today = todayLocal())
   ```
   `summary.js` 同步改为传对象。
3. 入口守卫：
   - `dailyMaxBudget` 非正整数 → `{ outstanding: 0, dates: [] }`；
   - `parseDate(accountingStartDate) === null` → 同上（防御性，正常不会触发）；
   - `earliest === null`（无任何记录）→ 同上；
   - `effectiveStart > today`（基准日在未来）→ 同上。
4. 有效起点（核心）：
   ```js
   const effectiveStart = accountingStartDate > earliest ? accountingStartDate : earliest;
   ```
   两个值都是 `YYYY-MM-DD`，字符串比较即等价于日期比较，无需再转 Date。这样既不会回退到基准日之前，也不会把起点推到最早记录日之后。
5. 遍历顺序与折算：
   - **起点空白段**：`leadingEmptyDays = diffDaysBetween(effectiveStart, rows[0].date)`，`> 0` 时执行 `applySavings(min(leadingEmptyDays, 30) * dailyMaxBudget)`。
     - 差值包含 `effectiveStart` 当天、不含首条记录日，正好对应「起始日那天没有记录，整份额度进结转池」。
     - 如果首条记录日就是 `effectiveStart`，差值为 0，不产生额外结余。
   - **中间空白段**：保持现有逻辑 `diffDaysBetween(prev, cur) - 1`，上限 30。
   - **末尾空白段**：保持现有逻辑 `diffDaysBetween(last, today) - 1`，上限 30（今天未结束，不计入已节省）。
   - 起始日之前的记录因 SQL 的 `date >= ?` 被直接排除，不产生超支、结余或结转。
6. 注释同步更新，说明 `effectiveStart` 的推导与「起点前记录只进总额」。

## 4. 假设与决策

1. **未设置时固定为当天，而不是每次请求取当天**：在 `getSettings()` 首次读取时写库一次，避免起点逐日漂移；这也是「开启功能的第一天」的可落地解释。
2. **清空基准日 = 重置为今天**：`PUT` 传 `null` 删除 key，下一次读取重新固定当天。
3. **基准日之前的记录仍计入 `currentBalance` / 总收支**：钱是真实发生的，只是不参与超支队列。
4. **未来基准日**：允许保存，但算法直接返回空（视为功能尚未开始）。
5. **今天不计入末尾空白日**：沿用上一轮修复，只折算已结束的日期，避免每天早上自动把红字抹平。
6. **升级后的直接影响**：默认固定为首次读取的当天（当前是 `2026-11-07`），因此 11-03 ~ 11-05 的历史记录不再参与超支，大盘的「待填补超支 ¥40.00」会变成 0；想保留历史口径，在设置里把基准日改成 `2026-11-03` 或更早即可。
