# v0.2 记账本 — 日期维度 + 行内编辑/删除 实施计划

## Summary

在已验收的 v0.1 骨架上做增量改造，范围严格限定为：

1. `records` 表新增 `date TEXT NOT NULL` 字段，默认当天
2. `POST /api/records` 接收 `date`；`GET /api/records` 支持 `?date=YYYY-MM-DD` 筛选
3. 前端加日期选择器，切换日期只显示该日记录，并显示该日消费合计
4. 每条记录支持行内编辑「金额 / 备注」，支持删除并弹确认

**不做**：时间轴、日历弹窗、标签、生存目标、兴趣预算、agent。新增/改造共 4 个文件，不引入任何新依赖。

已确认的两项决策：
- 总额口径：**所选日期的合计**，随日期选择器变化
- 旧数据：**保留并回填**，用 `created_at` 的日期补上 `date`

## Proposed Changes

### 1. `server/db.js` — 加列 + 幂等迁移

**做什么**

- `CREATE TABLE IF NOT EXISTS records` 的列定义中加入：

```sql
date TEXT NOT NULL DEFAULT (date('now','localtime'))
```

- 在 `db.exec` 之后追加迁移逻辑（因为旧库的表不会被上面的 `IF NOT EXISTS` 改动）：
  1. `SELECT name FROM pragma_table_info('records')` 判断是否已有 `date`
  2. 若无：`ALTER TABLE records ADD COLUMN date TEXT NOT NULL DEFAULT ''`（SQLite 的 ALTER 只接受常量默认值，不能写 `date('now')`）
  3. 紧接 `UPDATE records SET date = date(created_at) WHERE date = ''`，用创建时间的日期回填旧数据（`created_at` 形如 `2026-11-05 12:06:54`，`date()` 可直接截出日期）
- 迁移只在缺列时执行，重复启动无副作用。

**为什么**：满足「默认当天」，同时不丢已有 3 条记录。

### 2. `server/routes/records.js` — date 读写 + PATCH + DELETE

**做什么**

- 所有 SELECT 的列清单加 `date`；`toRecord` 输出增加 `date` 字段。
- 新增两个共享校验/工具函数：
  - `todayLocal()`：用本地 `getFullYear/getMonth/getDate` 拼 `YYYY-MM-DD`（**不用** `toISOString()`，避免 UTC 时区把日期推前一天）
  - `parseDate(raw)`：同时校验格式与真实性 —— 先匹配 `/^\d{4}-\d{2}-\d{2}$/`，再用 `Date.UTC` 构造后比对年月日，拒绝 `2026-02-30` 这类不存在的日期；不合法返回 `null`
- `GET /`：
  - 无 `date` 参数 → 沿用全量查询（`ORDER BY id DESC`）
  - 有 `date` 参数 → 校验，非法返回 400 `{ error: 'date 格式应为 YYYY-MM-DD' }`；合法走 `WHERE date = ? ORDER BY id DESC`
  - 两条预编译语句：`listStmt`、`listByDateStmt`
- `POST /`：
  - `date` 可选；缺省取 `todayLocal()`；提供了就 `parseDate` 校验，非法 400
  - insert 语句改为 `INSERT INTO records (amount_cents, note, is_hobby, date) VALUES (?, ?, ?, ?)`（列顺序与现有 `amount → note → isHobby` 校验顺序保持一致）
- `PATCH /:id`（新增，仅允许改金额/备注）：
  - `id` 用 `Number(req.params.id)`，非正整数 400
  - body 里 `amount`、`note` 至少出现一个，否则 400 `{ error: '没有需要更新的字段' }`
  - `amount` 出现则走 `parseAmountToCents`，非法 400
  - `note` 出现：需为字符串或 `null`；字符串 trim 后为空 → 存 `null`
  - 先 `getStmt.get(id)`，不存在 404 `{ error: '记录不存在' }`
  - 用两条预编译 UPDATE：只改金额、只改备注、两者都改（按命中字段选择，避免为省事写一条 `COALESCE` 造成「无法把备注清空」的语义问题）
  - 返回 200 + 更新后的完整记录
- `DELETE /:id`（新增）：
  - 非正整数 400；不存在 404；成功返回 204 无 body（前端按状态码判断）
- 不支持通过接口改 `date` 与 `is_hobby`：v0.2 明确不做。

**为什么**：API 与需求一一对应，且编辑语义明确（能置空备注）。

### 3. `client/src/App.jsx` — 日期选择、合计、行内编辑、删除

仍保持单组件，不抽 api.js / 不拆子组件（当前规模仍小，拆分会是过度设计）。

**做什么**

- 新增 state：
  - `selectedDate`（初始为本地今天，`YYYY-MM-DD`）
  - `editingId`、`draftAmount`、`draftNote`（行内编辑草稿）
  - `rowBusyId`（正在保存/删除的行 id，用于禁用按钮）
- `loadRecords(date)`：`GET /api/records?date=${date}`
- `useEffect` 依赖 `selectedDate`，切换日期即重拉
- 创建表单：`POST` body 增加 `date: selectedDate`；成功后清空金额并重拉当前日期列表（**新增不加备注输入框**，备注通过行内编辑补，避免超出范围）
- 顶部工具条：`<input type="date" value={selectedDate} onChange=...>` + 合计展示
  - 合计 = `records.reduce((sum, r) => sum + r.amountCents, 0)`，前端本地求和，不新增合计接口
  - 文案：`selectedDate` 等于今天时显示「今日合计 ¥x.xx」，否则显示「当日合计 ¥x.xx」
- 列表项（默认态）：金额、备注（无备注则不显示）、`createdAt` 时间（`slice(11,16)` 取 HH:MM）、「编辑」「删除」两个文字按钮
- 行内编辑态（`editingId === record.id`）：
  - 两个输入框：金额（文本 + `inputMode="decimal"`，初值 `(amountCents / 100).toFixed(2)`）、备注（文本，初值为 `note ?? ''`）
  - 「保存」→ `PATCH /api/records/:id`，body `{ amount, note: draftNote.trim() || null }`；成功后退出编辑并重拉
  - 「取消」→ 清空 `editingId`，不发请求
  - 请求失败：将后端 `error` 展示在行下方，保留编辑态不丢用户输入
- 删除：点击先 `window.confirm('确定删除这条记录？')`，取消则什么都不做；确认后 `DELETE`，204 则重拉列表
- 标题改为「记账本 v0.2」；`error` 展示沿用现有 `.error` 段落

**为什么**：需求里的每一项都落到具体交互，且不引入新状态管理方案。

### 4. `client/src/App.css` — 补齐新结构样式

**做什么**

- `.toolbar`：日期选择器与合计一行两端对齐（`display:flex; align-items:center; justify-content:space-between`）
- `.total`：合计用加粗、略大字号
- `.row-edit`：编辑态两个输入框 + 保存/取消按钮的 flex 布局，输入框沿用 `.form input` 的边框风格
- `.actions button`：文字按钮（无背景、主色文字、hover 下划线），删除按钮用 `#d83931`
- `.note`：备注灰色小字，单行省略（`overflow:hidden; text-overflow:ellipsis; white-space:nowrap`）
- 原 `.list li span:first-child / nth-child(2)` 这类按位置选中的规则改为语义 class（`.amount`、`.time`），因为行结构变了，位置选择器会失准

**为什么**：v0.1 的样式依赖 DOM 位置，不改会错位。

## Assumptions & Decisions

| 项 | 决定 | 理由 |
|---|---|---|
| 合计口径 | 所选日期的合计（已确认） | 与日期筛选保持一致 |
| 旧数据 | 保留并用 `created_at` 回填 `date`（已确认） | 不丢数据 |
| 默认日期 | 本地时区当天，前后端都用本地日期 | 避免 UTC 偏移导致跨日 |
| `date` 校验 | 严格 `YYYY-MM-DD` 且必须是真实日期 | 防脏数据 |
| 编辑范围 | 仅 `amount` / `note`，不含 `date` / `is_hobby` | 按需求 |
| 备注清空 | 前端空字符串 → 发 `note: null` | 语义清晰 |
| 删除确认 | `window.confirm` | 不做自定义弹窗，符合「不做日历弹窗/复杂 UI」的克制 |
| 新增表单 | 仍只有金额，不加备注输入 | 未要求，可在行内补 |
| 合计实现 | 前端对已加载记录求和 | 不新增接口 |
| 依赖 | 不变，无新增包 | 迁移与交互都无需新依赖 |
| 文件数 | 只改 4 个既有文件，不新建源码文件 | 最小改动 |

## Verification

1. **重启**：后台 `npm run dev` 已在运行，`node --watch` 会自动重载后端；前端改动由 Vite HMR 生效。
2. **迁移校验**（旧库已存在，重点看回填）
   - `PRAGMA table_info(records)` → 出现 `date`，`notnull=1`，默认值为 `''`（旧库）或 `date('now','localtime')`（全新建库）
   - `SELECT id, date, created_at FROM records` → 3 条旧记录的 `date` 与 `created_at` 的日期一致，无空值
3. **接口**
   - `GET /api/records?date=<今天>` → 只含当天记录；`GET /api/records?date=1999-01-01` → `records: []`
   - `GET /api/records?date=2026-02-30` 与 `?date=abc` → 400
   - `POST {"amount":"9.90"}`（不传 date）→ 新记录 `date` 为今天
   - `POST {"amount":"5","date":"2026-11-01"}` → 新记录 `date` 为 `2026-11-01`
   - `PATCH /api/records/:id {"amount":"3.5"}` → `amountCents: 350`；`PATCH {"note":"咖啡"}` → `note` 更新；`PATCH {}` → 400；`PATCH /api/records/99999` → 404
   - `DELETE /api/records/:id` → 204；再 GET 该日期不含此 id；`DELETE /api/records/99999` → 404
4. **前端验收**（浏览器 http://localhost:5173）
   - 日期选择器默认今天，新增 1 条后列表出现，合计随之增加
   - 切到无记录的日期 → 列表空、合计 `¥0.00`、文案为「当日合计」；切回今天 → 记录与合计恢复
   - 点「编辑」改金额 + 填备注 → 保存后行内展示新值，合计同步变化；点「取消」不改动
   - 点「删除」→ 弹出确认；取消后记录仍在；确认后记录消失、合计减少
   - 刷新页面（F5）→ 日期、记录、合计保持一致（新增的记录日期为所选日期）
5. **异常路径**：编辑时把金额改成 `abc` 保存 → 行下方显示后端错误，数据不变
